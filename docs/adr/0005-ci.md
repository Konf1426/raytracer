# 5. Run CI in the development image

## Context

The brief asks for automated checks on pull requests with the same container as
contributors. Native runner packages or a second CI Dockerfile could drift from
the editor environment.

## Decision

Propose GitHub Actions to build `.devcontainer/Dockerfile`, then run the tests and
a small render in that image. Check Debug and Release, and upload the render as a
workflow artifact. Also run on pushes and manual dispatch.

## Status

Proposed

## Consequences

Build tools are described once, and failed tests fail CI. Pull requests require
network access to the image registry and GitHub. Images are rebuilt per job,
which costs time. Linux CI does not validate native Windows or macOS. A local
workflow file is not evidence of a successful hosted run.
