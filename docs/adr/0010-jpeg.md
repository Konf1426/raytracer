# 10. Save JPEG previews with an isolated stb adapter

## Context

[Milestone m2](https://learn.glassworks.tech/raytracer/milestone-m2/) requires a
JPEG preview and a test that reads the saved file back. The m1 tag writes PPM;
renaming that output is not an encoder. Rendering already returns an Image of
linear RGB values, independently of file formats.

## Options

| Option | Fit and cost |
| --- | --- |
| [stb_image_write](https://github.com/nothings/stb/blob/6b5799bae8a1fe3792691ef4b72ae26434c3e799/stb_image_write.h) | A single header with JPEG encoding, no extra installed dependency, MIT or public-domain licensing. Its C API and byte buffer need an adapter. |
| [libjpeg-turbo](https://github.com/libjpeg-turbo/libjpeg-turbo) | A specialised JPEG encoder/decoder with SIMD support and libjpeg/TurboJPEG APIs. Additional build and API integration are more than this small preview needs. No local performance comparison is claimed. |
| External PPM conversion | Keeps the old encoder but adds an executable dependency and a second execution step to every render. It would also need installation and error handling. |
| [LodePNG](https://github.com/lvandeve/lodepng) | Encodes PNG, not the JPEG requested here. |

## Decision

Propose stb_image_write behind `save_jpeg(Image, path, quality)` in `image/jpeg`.
Vendor the two unmodified headers stb_image_write.h and stb_image.h from commit
`6b5799bae8a1fe3792691ef4b72ae26434c3e799`, retaining their licences and provenance.
This avoids an additional configure-time download. Use stb_image only in tests
and their CLI decoder. Dependency headers stay outside public project headers.
Compile each implementation macro once, in a separate target without our warning
flags. Upgrades require an explicit change of the snapshot and another test run.

The JPEG adapter converts top-to-bottom linear RGB into bytes using m1's policy:
clamp to [0, 1], square root (gamma 2), then round to [0, 255]. Default quality is
95; accept 1 through 100. Reject non-finite channels and invalid quality. Use a
binary C++ stream and stb's callback API so open, write and close errors become
exceptions. Select JPEG in main and retain the PPM library and its tests.

Do not introduce an image saver hierarchy: main is the only caller selecting a
format today, and a second free-function adapter is sufficient. Neither Image
nor Renderer needs to know about the encoder. This differs from the course's
ImageSaver example and is a deliberate cost/scope choice for the existing m1.

## Status

Proposed

## Consequences

JPEG is lossy, even at quality 100. Decode actual output in tests, check dimensions,
orientation and colours with a documented tolerance, rather than exact encoded
bytes. stb_image is a separate decoder but from the same collection, not an
independent interoperability certification. A third-party snapshot adds source
and maintenance responsibility. Retain its MIT notice (selected licence).
The byte buffer adds three bytes per pixel during export. Gamma 2 remains a
teaching approximation rather than exact sRGB.

PPM's small private byte conversion remains unchanged to preserve its m1 contract;
both adapters have tests against independently calculated transfer values.
Introducing shared encoding machinery would modify another working m1 file.
