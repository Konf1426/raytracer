# m1 delivery checklist

The [official milestone page](https://learn.glassworks.tech/raytracer/milestones)
sets m1's objective as a sphere lit by the sun on a floor, including tests, ADRs and
a domain model. Its deadline is November 22, 2026 at 23:59, Paris time. m1 is
evaluated together with m2 and is its starting point.

## Implemented

- [x] C++20, CMake, debug/release presets and warning flags.
- [x] Docker development environment and short Make commands.
- [x] Catch2 and CTest, with vector TDD observations.
- [x] Domain folders, AI instructions and proposed ADRs.
- [x] MIT licence chosen by the owner, contribution guide and templates.
- [x] CI definition using the development Dockerfile.
- [x] UML domain model and engineering review.
- [x] Vector, Ray, Sphere, Camera and Image, plus a floor and scene.
- [x] Sunlight, ambient light, shadow rays and PPM export.
- [x] Real 640 × 360 rendered preview included in the README.
- [x] 33 checks passed in native WSL Debug and Release.
- [x] 180 unit assertions passed with AddressSanitizer and UndefinedBehaviorSanitizer.
- [x] Fresh source copy built, tested and rendered as vscode in the development
  Docker image, in Debug and Release; all 33 checks passed in both.

See the [validation record](../engineering/validation.md) for versions, evidence
and limits.

## Before the final tag

- [ ] Owner reviews the implementation and can explain the maths and C++.
- [ ] Owner reviews and accepts or revises each proposed ADR.
- [ ] Validate the editor dev-container experience on a fresh checkout.
- [ ] Push reviewed changes and confirm the hosted CI run succeeds.
- [ ] Confirm the branch and that no existing m1 tag would be overwritten.
- [ ] Create and push the m1 tag on the reviewed commit.

Do not mark this milestone delivered merely because the implementation works.
The m0 report and tag remain the original discovery deliverable.

After review, from the dev container:

```sh
make build
make test
make run
git status
git branch --show-current
git tag --list
```

Inspect the changes, stage the intended files explicitly, commit, and push the
intended branch. When CI is green and m1 is absent, create `git tag m1` and push
it with `git push origin m1`. Do not force-update a pre-existing tag.
